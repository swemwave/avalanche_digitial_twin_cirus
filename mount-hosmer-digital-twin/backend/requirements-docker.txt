# Server-delivery (Docker) dependencies = the Windows dependency set, plus a
# PostgreSQL driver.
#
# Why this file exists rather than a line in requirements.txt:
#
#   The primary delivery mode is an offline, double-clicked .exe on Windows backed
#   by SQLite. That user never needs a PostgreSQL driver, and requirements.txt is
#   what they install. Keeping psycopg out of it keeps the offline install lean.
#
#   But `DATABASE_URL=postgresql+psycopg://...` is a documented, supported swap
#   (see .env.example and the `postgres` compose profile), and SQLAlchemy cannot
#   honour it without a driver. Shipping the Docker image without psycopg would mean
#   the documented Postgres profile dies at startup with ModuleNotFoundError. So the
#   server image carries it and the desktop install does not.

-r requirements.txt

psycopg[binary]>=3.2
